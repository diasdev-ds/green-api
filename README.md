# MAX Chat · GREEN-API

Веб-чат для отправки и получения текстовых сообщений в мессенджере MAX через [GREEN-API](https://green-api.com/max).
Интерфейс повторяет структуру [web.max.ru](https://web.max.ru/): список чатов слева, переписка справа.

**Стек:** React 18 + TypeScript + Vite. Без UI-библиотек и бэкенда: приложение обращается к GREEN-API напрямую из браузера.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # production-сборка в dist/
```

## Как пользоваться

1. Введите `idInstance` и `apiTokenInstance` из [личного кабинета](https://console.green-api.com).
   `apiUrl` определяется автоматически по первым 4 цифрам idInstance (`3100…` → `https://3100.api.green-api.com`), при необходимости его можно указать вручную.
2. Нажмите «+» и введите номер получателя (РФ `+7` или РБ `+375`), будет создан чат.
3. Напишите сообщение: оно уйдёт получателю в MAX.
4. Ответ получателя появится в чате автоматически.

**Настройка инстанса:** в личном кабинете должно быть пустое поле `webhookUrl` и включена опция «Получать уведомления о входящих сообщениях и файлах». Иначе ReceiveNotification вернёт ошибку.

## Как это устроено

| Задача | Метод GREEN-API |
| --- | --- |
| Проверка учётных данных при входе | `getStateInstance`: пускаем, только если инстанс `authorized` |
| Создание чата по номеру | `checkAccount`: получаем `chatId` пользователя MAX |
| Отправка | [`sendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/) |
| Получение | [HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/): цикл `receiveNotification` (long polling 5 с) → обработка → `deleteNotification` |

Детали, которые стоит отметить:

- **chatId, а не номер телефона.** Документация MAX рекомендует отправлять по `chatId` из `checkAccount`: входящие уведомления приходят с ним, а не с номером. Если `checkAccount` недоступен (например, лимит), чат создаётся по `номер@c.us`, а при первом ответе переключается на настоящий `chatId` по `senderPhoneNumber`.
- **Очередь не залипает.** Очередь уведомлений работает по FIFO, поэтому удаляются *все* уведомления, в том числе ненужные приложению (статусы инстанса, медиа). Иначе следующие сообщения не придут.
- **Без дублей.** Вебхук `outgoingAPIMessageReceived` может прийти раньше ответа `sendMessage`. Сообщения сверяются по `idMessage`.
- **Статусы доставки:** ✓ отправлено, ✓✓ доставлено, синие ✓✓ прочитано (из `outgoingMessageStatus`). Статус не откатывается назад, если уведомления пришли не по порядку.
- **Только текст** (по ТЗ): обрабатываются `textMessage` и `extendedTextMessage`, остальные типы пропускаются.
- **Устойчивость:** при сетевой ошибке опрос продолжается с нарастающей паузой (до 15 с), в шапке виден статус соединения.
- **Входящие от новых собеседников** автоматически создают чат.
- История и учётные данные хранятся в `localStorage` браузера, отдельно для каждого инстанса. «Выйти» удаляет учётные данные.

## Структура

```
src/
├── api/greenApi.ts            # тонкий клиент GREEN-API
├── store.ts                   # разбор уведомлений + reducer состояния чатов
├── hooks/useNotifications.ts  # цикл получения сообщений (HTTP API)
├── components/                # Login, Sidebar, ChatWindow, Avatar
├── utils/format.ts            # номера телефонов, время, инициалы
└── App.tsx
```

## Деплой

Сборка статическая (`base: './'`), поэтому `dist/` можно выложить на GitHub Pages, Vercel или Netlify без настройки.

## Ограничения

- GREEN-API для MAX принимает номера только РФ и РБ.
- Приложение работает без своего сервера, поэтому токен инстанса хранится в браузере. Для продакшена запросы стоит проксировать через бэкенд.
- Если открыть чат в двух вкладках, они будут конкурировать за одну очередь уведомлений.
